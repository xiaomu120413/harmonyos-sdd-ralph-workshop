# 架构与示意图替换清单

> 目标：让培训中的图真正承担“解释关系、支持判断、引导实操”的作用，而不是用小截图或一排卡片装饰页面。

## 审阅结论

当前 39 页授课版的主要问题不是配色，而是多数架构内容仍以“白底卡片 + 小字 + 细箭头”呈现：

1. 图与正文争抢注意力，投影后看不清节点和连线。
2. 有些页面把完整网页截图缩小放入 PPT，图中文字无法阅读。
3. 通用方法论图和项目真实架构图混在一起，学员不容易判断哪些是概念、哪些是当前仓库事实。
4. 图只说明“有哪些模块”，没有突出“输入从哪里来、在哪做判断、证据落在哪里”。
5. 多张图横向节点太多，没有视觉主路径，也没有失败分支或反馈回路。

建议把视觉分成两类：

- **通用方法论图**：优先采用官方图的结构，翻译并重绘成统一中文版本。
- **项目真实架构图**：只根据本地代码、文档和日志重绘，不套用社区模板。

## 本轮采用尺度

不机械要求“每页一图”，但只要有相关、清晰、可追溯的素材就应放入，避免课程只剩文字而显得单薄：

- **关键结构图优先**：第 2 页使用厂商中立的工作方式对比，第 3 页使用用户提供的演进案例图，第 4 页使用官方 Agent Flow，第 7 页用课堂反例加官方方法校正；第 24 页 E2E Runner 保留用户后续材料位。
- **真实证据有就放**：需求、RFC、Story、问题定位、日志、代码、测试报告页面，只要本地存在截图、Diff、目录、报告、时间线或界面，就选一项作为主视觉。
- **外部好图有就用**：SDD、上下文工程、MCP 等通用概念如果找到官方高质量图，可以引用或翻译重绘；找不到合适图时不勉强。
- **没有图片也不能空**：可用一段放大的真实日志、代码 Diff、结构化文档片段、验收结果卡或现场练习作为视觉主体。
- **不用无关装饰图**：不为了填满页面加入通用 AI 插画、无来源社区截图或与当前项目无关的复杂架构图。

## 四张必须重绘的课程自有图

### A. 复杂需求工程闭环

```text
意图/资产 → PRD/边界 → RFC/不变量 → Story/验收点
   ↑                                      ↓
决策/写回 ← 证据/状态 ← 真机/E2E ← 实现/测试
```

主线只用一种粗箭头；失败回路使用红色细箭头；每个阶段下只放一个真实文档名。

### B. Ralph 一轮运行

```text
读取一个 Story → 载入最小上下文 → 实现 → 验证 → Commit/写回
        ↑                                          ↓
        └──────── 新 Session 读取外部记忆 ──────────┘
```

外圈显示循环，内圈只放三个稳定资产：`story.json`、`progress.md`、Git/Tests。停止条件必须是可见节点。

### C. MDM 状态同步

```text
Account Event → Debounce/Coordinator → Stable Snapshot → Policy Projection
                         │                    │
                         └─ retry/timeout ────┘
```

用时间轴表现“事件先到、快照后稳定”，不要用模块清单代替状态语义。

### D. E2E Runner 四层泳道

```text
Case 层       Case JSON
编排层        Runner → SecurityToolAdapter → Flow Executor
执行层        MCP Driver → Bridge → Backend → MCP Tools
              HDC Driver → HDC/System Commands
证据层        Assertions → Result；Reporters → Artifacts
```

强调：Driver success 只进入事实收集，最终状态由 Assertion 决定。

## 统一视觉规则

1. 一张架构图最多保留 7 个主节点；更多节点按层或阶段折叠。
2. 主路径使用 2.5–3 pt 实线，反馈路径使用 1.5–2 pt 弧线，禁止箭头穿过文字。
3. 颜色表达语义而非装饰：蓝=执行，绿=证据/PASS，橙=环境或外部能力，红=失败/停止。
4. 每张图必须有一个视觉焦点，不能同时出现流程、表格、截图和四个结论框。
5. 外部原图放在讲师备注中记录 `[Sources]`；页面内使用翻译重绘时也要保留来源。
6. 项目事实图必须在备注中列出对应代码、RFC、Case JSON 或日志，避免“漂亮但无法穿刺”。
7. 投影环境下节点文字不低于 18 pt，主节点不低于 22 pt；整页网页截图不作为架构图。
