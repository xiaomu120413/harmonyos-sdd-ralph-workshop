# 阶段 1｜资产同步与冲突清单

## 1. 阶段目标

不是把所有文件一股脑塞给 AI，而是建立一个“来源可追踪、冲突可见、缺口明确”的需求基线。同步完成的标志不是文件数量齐全，而是每个需求都能说明来源、当前解释、实现状态和待决策项。

## 3. AI 的同步动作

AI 不直接生成代码，先生成四张表：

1. **资产清单**：文件、版本、日期、用途、可信边界。
2. **术语表**：`public/private/custom`、规则类型、用户级 policy、rule intent、deployment、账号快照。
3. **冲突矩阵**：同一概念在不同资产中的表达是否一致。
4. **缺口清单**：没有失败语义、没有平台证据、没有测试或没有实现映射的项。

推荐提示结构：

```text
只读同步这些资产，不提出实现。
逐条输出：来源、原文、AI 解释、代码现状、冲突、待决策、证据路径。
没有证据的结论标 UNKNOWN；不要把较新的文件自动当成正确答案。
```

## 4. 真实冲突：公共/专用模式被 AI 修正版误当成规则类型问题

### 原始输入

`REPO FACT`：原始 Excel 第 4 行：

> 提供不同场景下的缺省防火墙配置，如公共、专用和自定义。

### AI 修正版

`REPO FACT`：AI 修正版第 4 行改成“IP、域名、DNS 三种规则类型”，并写出“公共、专用为 Windows 防火墙概念，HarmonyOS 不区分网络类型”。

### 当前仓库事实

- PRD 明确要求 `public/private/custom` 三种主模式。
- 模块设计明确 `FirewallPresetMode = public | private | custom`。
- `FirewallPage.ets` 展示三张模式卡。
- `FirewallModeStrategy.ets` 为 public/private 生成不同预置规则。
- IP/DOMAIN/DNS 在当前设计中是**规则类型**，不是对主模式的替代。

### 决策

保留两条正交维度：

```text
主模式：public / private / custom
规则类型：IP / DOMAIN / DNS
```

这条冲突说明：AI 的平台映射是候选解释，不是产品决策。资产同步必须把“平台 API 的概念”和“产品抽象”分开。

## 5. 同步后的需求卡示例

```yaml
requirement_id: FW-MODE-001
source:
  - 原始需求清单.xlsx!Sheet1:C4
  - PRD.md#7.2
term: 防火墙主模式
decision: 保留 public/private/custom 产品模式
implementation:
  - FirewallPage.ets
  - FirewallModeStrategy.ets
tests:
  - mode-strategy.test.ets
  - scripts/e2e/cases/firewall/mode_cards.json
conflict:
  source: AI修正版.xlsx!Sheet1:C4:E4
  resolution: 规则类型与主模式是两个维度
status: RESOLVED
```

## 6. 阶段出口门

只有同时满足下列条件，才能进入方案推导：

- 每条关键需求有 ID 和来源。
- 术语冲突已决策或明确标记待决策。
- PRD、设计、代码和测试能形成初步映射。
- 未验证的平台能力单独进入“技术穿刺”，没有藏进需求结论。
