# 外设管理案例｜证据状态总表

> 这张表是案例的“事实入口”。课堂上的每个结论都应能回到一个真实文档、代码、测试或设备结果；没有证据的地方明确标记 `PENDING`，不靠口头补齐。

## 1. 证据分级

| 等级 | 能证明什么 | 不能证明什么 |
|---|---|---|
| `D1 文档` | 需求、边界、决策和验收口径已写清 | 代码已经实现 |
| `D2 代码` | 责任边界和实现路径存在 | 分支在运行时一定正确 |
| `D3 UT` | 隔离条件下的分支、不变量和回退逻辑 | MDM 系统状态真实改变 |
| `D4 构建/安装` | 工程能编译、签名、安装 | 业务结果正确 |
| `D5 E2E/UI` | 真机页面可达、操作可执行、可见状态符合预期 | 系统 MDM 真源一定与页面一致 |
| `D6 系统回读` | MDM/USB 系统接口回读与预期一致 | 长时间、跨重启、全设备矩阵都稳定 |
| `D7 实物行为` | U 盘/摄像头/打印机等真实接入结果 | 未覆盖的设备类型同样正确 |

课堂判定只使用四种状态：`PASS / FAIL / UNKNOWN / PENDING`。`UNKNOWN` 是证据不足，不是“基本通过”。

## 5. 必须补拍的证据位

| 编号 | 操作 | 画面/数据 | Oracle |
|---|---|---|---|
| V1 | 默认 allow，插入新 U 盘 | UI 白名单记录 + 系统允许 + trace | 新 fingerprint 出现，`desired=allow`，不下发 deny |
| V2 | 默认 deny，插入新 U 盘 | UI 黑名单记录 + 系统拒绝 + trace | 只有系统 deny 成功后才写 `desired=deny/active=deny` |
| V3 | 黑名单设备拔出再插入 | 拔出内部 allow、重插重新 deny | 逻辑策略保留；拔出不新增伪造策略快照 |
| V4 | 全局禁用时查看黑白名单 | 规则仍显示、选择器置灰 | `desiredPolicy` 不变，`activePolicy` 收敛为 none |
| V5 | 全局恢复 | 在线 deny 被重放 | 系统回读 + 状态库 + 实物接入三者一致 |
| V6 | USB 存储 DISABLED 下尝试单设备 allow | UI 禁用或后端拒绝 | 不出现假成功，提示指向冲突与还原入口 |
| V7 | 人为制造 MDM 下发失败 | UI 回到旧值、reasonCode、系统状态 | 状态不提前提交，失败可重试 |
| V8 | 执行“还原策略” | EDM 残留清空、卡片保留为 allow | 本地与系统同时恢复；记录不被误删 |

## 6. 课程使用规则

1. 先展示结论，再展示它对应的证据等级。
2. 代码截图只证明实现路径；涉及 MDM 真相必须补系统回读或实物行为。
3. 失败报告与通过报告并排展示，说明迭代而不是隐藏失败。
4. 任何没有 D6/D7 的结论都使用“代码/单测已证明”“UI 路径已证明”，不使用“设备已完全验收”。
