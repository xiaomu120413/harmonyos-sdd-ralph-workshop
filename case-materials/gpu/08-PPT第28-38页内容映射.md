## 3. 第 33–36 页的讲授链

### 第 33 页｜先拆任务

```text
穿刺证实了边界
  → 按风险闭环拆 T00–T07
  → 每张卡写 Allowed / Forbidden / Verify / Stop
  → 进入门没过，不开始下一任务
```

### 第 34 页｜再看实际开发

```text
T01 先把 bridge 和 hardware decoder 真正带进产物/设备
  → T02 证明一份压缩输入产生合法 native output
  → T03 证明 owner 唯一且只在 matched EndFrame present
```

这页不画人/多 Agent 抽象泳道，直接展示“改哪个符号—得到什么证据—不通在哪里停”。

### 第 35 页｜把开发写成运行账

| 轮次 | 唯一未知 | 本轮证据 | 下一步 |
|---|---|---|---|
| R1 | bridge 是否进入目标 HAP | symbol / library identity | 只有 PASS 才进 R2 |
| R2 | 真机是否选硬件 decoder | capability / decoder name | 不支持则停在 UNSUPPORTED |
| R3 | input/output 是否可关联 | frameId/PTS/format/stride/planes | 输出合法才进显示 |
| R4 | owner/EndFrame 是否正确 | pendingFrameId/matched present | 黑屏则找第一处异常 |
| R5 | 连续播放是否有界 | queue depth/age/drop/CPU/FPS | 决定队列和背压任务 |

### 第 36 页｜遇到问题只修第一处异常

| 现象 | 先看什么 | 不要先做什么 |
|---|---|---|
| decoder 有 output 但黑屏 | native import → composite → pending → matched EndFrame → target generation | 直接猜 shader |
| 粉/绿色块或花屏 | format / stride / planes / rect / retained background | 盲改色彩矩阵 |
| 刚开始流畅，随后变卡 | queue depth / age p95 / decodeUs / present gap | 直接增加线程 |
