# 阶段 5｜最小能力穿刺计划

## 目标

沿最终架构跑通“一条命令、一份压缩输入、一个硬解输出、一次正确 present、一次可解释 fallback”。

## 穿刺步骤

| ID | 动作 | PASS | FAIL / UNKNOWN |
|---|---|---|---|
| SP-01 | 编译并链接 OHOS backend | arm64 build 与 symbol/link 证据 | 只构建 App 或 backend 未入产物 |
| SP-02 | 真机创建硬件 decoder | capability、decoder name、configure/start 成功 | 运行时仍选择软件路径 |
| SP-03 | 输入一个 AVC420 sample | frameId、bytes、queue result | 输入被拒绝或无法关联 |
| SP-04 | 取得合法输出并显示 | size/format/stride/planes + owner + present | callback 成功但 buffer/owner 未证实 |
| SP-05 | 注入失败 | fallback reason 与旧路径恢复 | 静默吞错或停在黑屏 |

## Forbidden

- 不提前实现 AVC444 全链路。
- 不删除 OpenH264/FFmpeg/GDI fallback。
- 不做 zero-copy 优化。
- 不用单张截图替代 frame trace。

## 产物

```text
spike/<runId>/
├── identity.json
├── build.log
├── selected-decoder.log
├── input-output-frame.log
├── output-description.json
├── present.log
├── fallback-injection.log
└── verdict.md
```

## 结束条件

穿刺 PASS 只证明对接方向成立；连续性能、AVC444、resize 和长稳进入后续任务，不能从一帧成功外推。
