# 阶段 5｜AVC420 最小能力穿刺

## 1. 唯一目标

沿最终架构跑通一条最短真实链：bridge attach → hardware decoder → 一份可关联 output → native buffer → retained composite → matched EndFrame present；并证明接管前失败仍能调用 original GDI。

本穿刺只回答“方案的关键接口方向是否成立”，不回答连续性能、AVC444、生命周期或长稳。

## 2. 进入条件

- `00` 中源码事实没有冲突，运行事实仍允许为 `PENDING`。
- `04-ADR-GPU-001-HarmonyOS硬解方案.md` 状态为 Accepted。
- 源码基线能定位 `bridge_attach`、AVC420 candidate、`ProcessCommand`、`OH_AVBuffer_GetNativeBuffer`、`PresentEndFrame` 和 original callback。
- 已冻结目标设备、服务端、分辨率、片段和 evidence identity 格式。
- 工作区既有改动已识别，不覆盖不属于本穿刺的修改。

若任一项不满足，输出 `NOT READY`，不开始编码。

## 3. 修改边界

**Allowed：** bridge/decoder/compositor 的最小接线、路径和同帧诊断、可恢复 fault injection、穿刺脚本。

**Forbidden：**

- AVC444 全链路；
- zero-copy 或性能优化；
- 删除 original SurfaceCommand、OpenH264/FFmpeg/GDI fallback；
- 无界线程、无条件清队列或 UI 无关修改；
- 用单张截图、API 返回成功或 build success 替代 frame trace。
