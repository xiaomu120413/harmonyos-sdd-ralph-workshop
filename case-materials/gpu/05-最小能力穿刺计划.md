# 阶段 5｜最小能力穿刺计划

## 目标

沿真实源码架构跑通“一次 bridge attach、一条合法 command、一份压缩输入、一个可关联 native output、一次 retained composite、一次匹配 EndFrame present、一次 original GDI fallback”。

## 穿刺步骤

| ID | 动作 | PASS | FAIL / UNKNOWN |
|---|---|---|---|
| SP-01 | 编译并链接 OHOS RDPGFX bridge 与 App compositor | arm64 build、`bridge_attach`/compositor symbol、HAP 库身份 | 只构建 App、加载旧库或 bridge 未入产物 |
| SP-02 | 真机创建硬件 decoder | capability、decoder name、configure/start 成功 | 运行时仍选择软件路径 |
| SP-03 | 输入一个 AVC420 sample | frameId、bytes、queue result | 输入被拒绝或无法关联 |
| SP-04 | 取得合法 native output 并在匹配 EndFrame 显示 | size/format/stride/planes + native import + pendingFrameId + owner + matched present | callback 成功但 buffer/owner/frame boundary 未证实 |
| SP-05 | 在 takeover 前注入失败，并验证 takeover 后恢复策略 | failure reason、consumed=false/original callback、owner transition 与 GDI 恢复 | 静默吞错、GPU/GDI 双写或停在黑屏 |

## Forbidden

- 不提前实现 AVC444 全链路。
- 不删除 original SurfaceCommand、OpenH264/FFmpeg/GDI fallback。
- 不做 zero-copy 优化。
- 不用单张截图替代 frame trace。

## 结束条件

穿刺 PASS 只证明对接方向成立；连续性能、AVC444、resize 和长稳进入后续任务，不能从一帧成功外推。
