# GPU 文档控制链｜先改文档，再改代码

GPU 改造跨越 FreeRDP、HarmonyOS AVCodec、NativeBuffer、EGL、帧语义和真机验收。聊天结论不能直接成为实现输入；每个阶段必须把事实、决策、边界和证据门写入版本库，下一阶段只消费已经审阅的文档。

## 1. 固定顺序

```text
需求/异常
  → 更新事实状态与基线
  → 更新源码地图或调研
  → 冻结/修订 ADR
  → 新建或修订 Story Worker Packet 与 AC
  → 提交文档 checkpoint
  → 最小代码修改
  → 构建/真机重放/故障注入
  → 更新 progress 与 evidence index
  → 代码和证据提交
  → 独立验收
```

任何会改变 decoder、buffer、owner、EndFrame、fallback、queue、lifecycle 或验收结论的代码修改，都必须先落到对应文档。只修拼写、链接或排版且不改变行为时，可不修改 ADR/Story，但提交说明必须写明原因。

## 2. 文档职责和变更触发器

| 文档 | 唯一职责 | 何时必须先改 | 下游消费者 |
|---|---|---|---|

| `01-问题与基线.md` | 冻结场景与 before 口径 | 设备、网络、分辨率、片段、指标口径变化 | S0、A/B 验收 |
| `02-大代码库认知地图.md` | 控制检索范围与上下文 | 入口、模块职责或下一轮阅读范围变化 | `09`、`03` |
| `09-源码调用链与任务拆解.md` | 保存真实调用、分支与 owner | hook、consumed、fallback、present 顺序变化 | ADR、Story |
| `03-跨平台实现调研.md` | 保存契约、差异和能力 GAP | 新平台 API/格式/生命周期事实出现 | ADR |
| `04-ADR-GPU-001-*.md` | 冻结方案和 Deferred | 责任边界、不变量、fallback 或方案选择变化 | Spike、Story |
| `05-最小能力穿刺计划.md` | 证伪最大未知 | Spike 输入、步骤、证据或 verdict 变化 | Story 拆分 |

## 3. 每次提交的原子边界

| 提交 | 必须包含 | 禁止混入 |
|---|---|---|
| Docs checkpoint | 受影响文档、Story/AC、待证未知 | 未经审阅的大规模代码实现 |
| Story implementation | 当前 Story 允许范围内的代码、测试、构建证据索引 | 后续 Story、无关重构、验收口径放宽 |
| Evidence update | 原始日志/CSV/媒体索引、progress verdict、状态表更新 | 生产代码修改 |
| Acceptance verdict | 独立复查结果、失败项和下一 Story | 为使结果变绿而修代码 |

推荐提交信息：

```text
docs(gpu): freeze S3 owner and EndFrame contract
feat(gpu): implement S3 matched-frame present
evidence(gpu): archive S3 device run <runId>
test(gpu): record S3 reviewer verdict
```

## 4. 阶段文档生成协议

新建或改写文档时，先输出并审阅以下控制字段，再写正文：

```text
Question: 本文档要减少的唯一未知
Input: 允许读取的源码、日志、媒体和上游 verdict
Facts: 可回到 path::symbol、runId 或用户决定的事实
Inferences: 基于事实的推导及可证伪条件
Pending: 当前缺失的证据
Decision: Reviewer 接受/拒绝/延后的选择与理由
Output: 下一阶段直接消费的字段
Stop: 证据不足时在哪里停止
```

AI 只负责检索、对照、提出候选和生成可审阅草稿；Reviewer 必须核对源码锚点、运行身份和推断边界。未经 Reviewer 冻结的建议不得进入 ADR 或生产代码。

## 5. 文档变更检查

每轮实施前：

```powershell
git diff -- case-materials/gpu
rg -n "PENDING|UNKNOWN|FAIL|PASS" case-materials/gpu/00-证据状态总表.md case-materials/gpu/06-工程验收计划.md
rg -n "Source Scope|Forbidden|RED / Probe|伪代码|验收点|Stop" case-materials/gpu/13-GPU-Ralph-Story拆分与伪代码验收.md
```

每轮提交前：

```powershell
git diff --check
git status --short
git diff --name-only
```

Reviewer 必须确认：文档先于代码、代码没有越过 Story、原始证据未被摘要替代、`PENDING/UNKNOWN` 没有在无证据时变成 `PASS`。

## 6. 冲突处理

当源码、ADR、Story 和运行结果互相矛盾时，优先级不是“最后修改的文件”，而是：

1. 当前 runId 的原始运行事实；
2. 当前 commit 的源码行为；
3. 已冻结的 ADR 与 Story 不变量；
4. 历史 Session 和媒体；
5. AI 的解释。

发现冲突后立即停止实现，把差异写入 `07-开发排障复盘.md`，再决定修代码、修文档还是把状态降为 `UNKNOWN/NEEDS_REPLAN`。
