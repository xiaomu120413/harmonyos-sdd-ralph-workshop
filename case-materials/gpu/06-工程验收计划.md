# 阶段 6｜工程验收计划

## 1. 四层正确性

| 层 | 核心问题 | 主证据 |
|---|---|---|
| 方案 | 是否沿用 FreeRDP 与成熟平台契约 | 调研表、ADR、原生调用链 |
| 实现 | 是否只修改授权边界 | Task Card、diff、UT、build |
| 路径 | 真机是否真的运行新 backend | decoder/path/frame/owner/present 日志 |
| 结果 | 同场景是否改善且工程回归可控 | CPU/FPS A/B、视频、长稳、矩阵 |

## 3. 判定规则

- `PASS`：主断言有独立证据。
- `FAIL`：证据已否定断言。
- `UNKNOWN`：缺证据；不得使用“应该”“看起来”补齐。

## 4. 结果视频边界

`gpu-validation-video-playback-16s.mp4` 可证明某次运行可见播放和交互，不能单独证明 CPU 性能、decoder 路径和长稳。完整验收需要绑定同一 runId 的日志与性能 CSV。

所有未入库数据及空白值统一见 `00-证据状态总表.md`。
